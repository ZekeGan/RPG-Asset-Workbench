## 待處理／討論問題

> 以下保留原始提問；定案狀態以本文件末尾「最新確認」為準。

1. **版號仍顯示 0.4.0**：使用者回報版本未升。前輪依「不自行升版」規則保留原版號；下一個版號與升版範圍待確認，後續需一致處理 package.json、package-lock.json 與介面顯示，避免各自硬編碼失同步。
2. **返回首頁入口重複**：「專案首頁」按鈕與「RPG 圖片管理器」標題都可返回首頁。討論保留一個或兩個，以及標題是否只顯示名稱；尚未定案。
3. **批量匯入與配對圖片預覽**：使用者要求已匯入圖片顯示預覽，能直接辨識內容。後續先核對現有預覽何時缺失／未出現，再修正；不得直接把需求當成已完成。
4. **圖片像素限制**：某項目上傳出現 `Input image exceeds pixel limit`。目前 src/main/png.ts 的 MAX_PIXELS 為 16,777,216，傳入 sharp 的 limitInputPixels；限制的是總像素數，並非要求寬高各不超過 4096。尚未取得出錯圖片尺寸，不宣稱已重現。待討論是否保留、調整或採其他方案，評估解碼記憶體與穩定性、較大素材支援、處理速度及錯誤提示。尚未決定移除或放寬限制。

## 後續開發需求（原始記錄，實作狀態見文末）

1. **多語言**：在現有中文版外新增英文、日文；語言切換按鈕放在專案首頁。後續確認翻譯涵蓋範圍及語言偏好保存方式。

3. **單張圖片拖放至指定素材**：將一張外部圖片拖到某素材列的「目前替換圖片」欄，開啟「上傳替換圖片」確認視窗，使用者確認後才保存版本；不直接寫入遊戲。沿用靜態 PNG、圖片差異確認及原始基準保護規則。
4. **多張拖放分流**：拖入多張圖片時才進入「批量匯入與配對」。單張落在指定欄位以外的行為尚待確認，不自行猜配素材。
5. **產品命名提案**：產品名稱改為 `RPG Asset Workbench`，TITLE 名稱改為 `R-aW`。先討論名稱的辨識度、易記性、搜尋與後續功能擴充潛力；TITLE 指視窗標題或介面品牌顯示等具體範圍，需在實作前釐清。此處指工具產品名稱，不是使用者建立的遊戲專案名稱；本輪不修改任何名稱或套件識別。

## 捲軸問題記錄 — 2026-10-24（後續已授權修正，見下方結果）

使用者要求本輪不開發程式碼。

1. Electron 最外層出現非預期捲軸。靜態檢查發現入口已不載入舊 style.module.css，其中 body 的 margin: 0 因而未生效；工作臺仍為 100dvh，瀏覽器預設 body 邊距是明確的溢出來源，其他容器是否溢出仍待尺寸驗證。方案：以獨立全域樣式恢復根節點／body 的邊距、尺寸及 box-sizing 基礎設定，讓應用外殼固定於視窗內；內容由各自捲動區承接。不能只隱藏外層捲軸而裁切內容。
2. 所有應用內捲軸應統一為素材工作臺風格。以目前側欄的深色軌道、灰綠滑塊、圓角及 hover 配色為共用基準，抽成全域規則／變數，涵蓋首頁、素材列表、批量配對、設定、歷史及彈窗；清理衝突的局部規則，水平捲軸亦一致。不影響作業系統原生選檔視窗。

後續驗收：四語及窄／一般視窗下，根頁面無非預期水平或垂直捲動，頁尾與操作按鈕可達；長內容在指定區域正常捲動，彈窗與全視窗圖片預覽不裁切。只補充受影響的 UI／尺寸檢查，不無故重跑資料層完整測試。

### 修正結果

使用者指示「執行」後已完成：新增入口載入的 global.css，清除 body 預設邊距並限定根容器尺寸；原有內容捲動區保留。全域捲軸沿用側欄深色灰綠設計（含水平捲軸），移除列表／側欄／選圖區的局部覆寫。

typecheck、build、Windows Electron fixture UI 驗收通過；四語首頁 1120×780、工作臺與設定 800×600，以及拖放／批量／放大畫面增加根頁面水平與垂直溢出檢查，並檢查各捲動區統一使用 thin 捲軸。截圖更新於 evidence/languages-drag；人工檢視日文工作臺頁尾與英文長設定彈窗。未重跑無關資料層測試，未操作真實遊戲。

效率回顧：沿用現有四語 UI 流程，只加入尺寸與共用捲軸斷言，避免另建重複測試或重跑完整資料回歸。
