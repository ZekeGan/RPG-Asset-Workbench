## Windows 更新與啟動

先關閉舊程式，解壓到新資料夾；不要同時開新舊版本。工具資料保留在 Electron userData，原始碼資料夾不是專案備份位置。

```powershell
npm ci
node node_modules/electron/install.js
npm run native:electron
npm run dev
```

如需本機原生編譯，使用既有 Python 與 Visual Studio C++ Build Tools。Windows 打包：`npm run pack:win`；本環境未驗證其產出。回到 Node 測試前先 `npm run native:node`，再執行 `npm run typecheck`、`npm test`、`npm run build`；再次啟動 Electron 前重建 Electron ABI。

## 本輪手測清單

只使用可拋棄的乾淨遊戲測試副本，MV-U／MV-E／MZ-U／MZ-E 各跑一次。

1. 建立專案：先選資料夾，看引擎與加密辨識，確認來源後建立；取消選擇不建案。關閉重開，原圖與專案仍在。
2. UI：1120×780 及較小視窗測匯出／群組／上傳彈窗，底部「專案清單已讀取」不可遮住彈窗；Tab 焦點留在彈窗，Escape 返回。工具列收合後列表變高、搜尋保留。
3. 對照封裝內 Mockup：首頁、建立、工作臺、詳細、套用／還原頁的排列與功能。檢查中文、長檔名和 Windows 字型。
4. 素材：100% 預覽、縮放拖曳；群組多重加入／移除。刪群組不刪素材或版本。
5. 匯入：單張與批量匯入、尺寸差異確認、未配對手動選擇、重複目標拒絕；匯入後遊戲檔仍不變。匯出加密來源應得到普通可解碼 PNG。
6. 套用：確認目標後套用；開遊戲確認圖片顯示。關遊戲後還原，再進遊戲驗證原圖。對比遊戲檔 SHA-256；還原後應等於原始檔，非目標檔不得變更。
7. 外部變更：修改測試副本的目標圖片後，套用／還原應阻擋。移動整份遊戲後重新連結，錯誤內容應拒絕。
8. 重啟：版本、active／deployed、群組、操作紀錄應保留。若出現未完成操作，先確認恢復，不能直接進行其他修改。

故障注入僅在自製測資中執行，不要求對日常遊戲測磁碟滿或強制斷電。

## 未完成與限制

- 刪除專案入口待 OPEN-005 決定。具體提案：放在「專案設定」最下方獨立危險操作區，紅色「刪除此專案」；先確認專案名稱與不可逆資料範圍。有部署／未完成操作再要求明確確認「保留遊戲現況，永久放棄還原／恢復」。清理失敗保留紀錄並提供重試，不顯示成功。本提案尚未視為已核准。
- Windows 原生 GUI／對話框、鎖檔、打包與四格真實遊戲顯示待人工驗證。瀏覽器 UI 檢查使用 mock IPC，不能代替 Electron 整合測試。
- 專用 worker／utility process、數萬素材效能、真實斷電／磁碟滿與恢復期間程序終止尚未完整覆蓋。
- 不支援 APNG、自訂加密或其他圖片格式。單檔 32 MiB／16,777,216 像素資源限制；批量最多 2000 檔、提交暫存上限 128 MiB，超過會明確拒絕。
- 掃描取消／中斷保留已完成素材，尚無續掃入口；不將部分掃描結果當完整可套用專案。
- 現階段沿用 user_version=1 與附加資料表初始化，未完成獨立版本化 migration／降版策略；更新後不保證舊版可安全操作新增狀態。
