# AI Coding Agent 專案規則

版本：1.0.0｜日期：2026-10-22｜規格基準：R0.9。

## 1. 必讀文件與開始條件

依序閱讀：docs/PRD.md、docs/ARCHITECTURE.md、docs/TEST_PLAN.md、docs/SPEC_REVIEW.md、design/INDEX.md。此套件只有規格與歷史原型，沒有正式應用程式。當前授權是文件製作，不等於授權初始化、安裝、實作或寫入遊戲；取得後續明確開發指令才開始。

使用者最新明確決策優先；同步PRD後再實作。PRD為產品行為唯一權威；ARCHITECTURE是Proposed，不能覆蓋PRD；TEST_PLAN是驗收依據；原型/Mockup只依design索引用途使用。衝突先指出並處理，不擅自選一個方便實作的行為。

## 2. 不得擅自變更的範圍

- 保留FR-001～FR-030、SCREEN-001～014、GAP-001～013、DEC-001～024識別碼；新增用新號，不重新編號既有項目。
- PoC/MVP只接受可解碼靜態PNG，APNG/其他格式阻擋；動畫與轉檔Future。不得沿用早期多格式決策。
- Windows、MV/MZ四格PoC不可自行縮為只MV或只未加密。
- 原始基準不可覆寫；active/deployed分離；匯入不寫遊戲；不能假稱成功或已恢復。
- 外部變更阻擋套用/還原，不增加強制覆蓋開關。
- 歷史刪除禁止active/deployed；整個專案刪除則依FR-030，允許明確放棄恢復與保留部署結果，不得擅自重新禁止。
- 不在未確認的UI範圍重畫，工作臺採W6配置、既有深色方向；新增刪專案入口位置先提出具體方案。
- 不修改遊戲程式/事件/外掛，不加入AI、雲端同步或其他未要求功能。

## 3. 程式碼與目錄規劃

正式初始化後可採以下候選結構，若調整須同步ARCHITECTURE，不需為純內部檔名逐一問使用者：src/main（服務/檔案）、src/preload（窄IPC）、src/renderer（React UI）、src/shared（契約）、tests/unit、tests/integration、tests/e2e、tests/fixtures、docs、design。

正式碼不從原型的localStorage/示意加解密直接當生產實作。遊戲測資、金鑰、個人圖片、DB、快取、備份不可提交版本庫；使用自製或有權使用且可分享的最小fixture。沒有正式倉庫前不自行git init。

主程序負責路徑與權限邊界；renderer不得拿到任意讀寫/刪除能力。以project/asset ID解析路徑，驗證輸入。保留既有使用者改動；不得清空未辨識目錄或透過連結刪外部資料。

## 4. 需求變更流程

1. 指出變更涉及FR、SCREEN、DEC及現行規則。
2. 使用者若已明確批准，不重問；若會改變行為且尚未批准，提出選項並等待，不自行補造決策。
3. 更新PRD與變更紀錄，再同步架構/測試/設計差異。不是所有技術細節都要使用者決定；可在既有範圍內作可逆實作選擇並記錄理由。
4. 保持同一版本基準。任何無法決定者用OPEN編號記錄影響與決定時點，不標成完成。

## 5. 測試要求

修改功能時查對FR與TC。修復行為缺陷要加入能重現原錯誤的測試，避免只照實作重寫測試。依風險執行受影響單元/整合/E2E；涉及檔案寫入、恢復、刪除需覆蓋故障與資料完整性。UI低風險文字/樣式修改不必新增形式化測試，仍需適當檢視。

只能在使用者指定、可拋棄的遊戲副本測寫入；任何驗證前記錄基準與環境。不可對使用者日常遊戲或外部資料執行故障注入。故障測試不得摧毀唯一備份。

四格相容性都需人工遊戲內確認，工具預覽不能代替。因缺少遊戲/Windows/權限而未執行時，列為BLOCKED或NOT RUN，不當PASS。

## 6. 必須執行的驗證流程

文件階段：編號/交叉引用/相對連結/階段/已取代決策一致性檢查。不得稱為應用程式測試。

獲准開發後：先讀實際package scripts與環境，執行存在且相關的型別檢查、lint、測試與建置；本套件尚無這些命令，禁止捏造已執行npm test等結果。每個垂直切片只加必要依賴，固定版本並說明。

寫入功能：比對操作前後hash、非目標檔案、部署metadata；驗證故障後回復。刪除功能：檢查限定清單、其他專案與外部檔案不變；未完成刪除準確回報。停止 optional 測試於風險已足夠驗證時，不無限擴大工作。

## 7. 交付與報告格式

每次交付包含：

- 版本/變更摘要：原因、涉及FR/SCREEN、改變的可見行為。
- 檔案與架構影響：關鍵檔案、是否改動Proposed方案、未決項。
- 驗證表：TC或命令、環境、PASS/FAIL/BLOCKED/NOT RUN、證據路徑。
- 資料完整性：寫入/還原/刪除時的實際結果與限制，不只列程式退出碼。
- 剩餘風險與下一步：需要誰提供什麼、是否具備進下一階段條件。

不把文件完成、Mockup完成、示意狀態跳轉當正式功能完成。不自動部署、發版、修改外部倉庫或開始下一開發階段。
