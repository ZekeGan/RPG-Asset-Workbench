# Test Plan — RPG Maker 圖片替換工具

版本：1.0.0｜日期：2026-10-22｜對應PRD/ARCHITECTURE 1.0.0，R0.9。

歷史規格階段的 NOT RUN 記錄保留；實際實作結果見根目錄 docs/TEST_REPORT.md。2026-10-23 核心更新驗收見根目錄 docs/DEVELOPMENT_0.5.md，涵蓋 TC-011/013/018/020/023/026/027 的新增行為；不可把歷史未執行或舊版 PASS 當作本輪結果。

## 1. 測試層級與策略

| 層級 | 規劃內容 | 主要需求 |
|---|---|---|
| 技術可行性 | 引擎識別、加解密、PNG解析、持久化/檔案恢復 | FR-002, FR-008, FR-018～FR-022, FR-029 |
| 單元 | pending狀態、版本號/刪除保護、群組關聯、配對唯一性、範圍解析、格式與差異分類 | FR-004, FR-007～FR-009, FR-011～FR-015, FR-020 |
| 整合 | DB/檔案一致性、批次撤回、備份、adapter寫入、位置鎖、清理邊界 | FR-013, FR-017～FR-024, FR-030 |
| E2E | 頁面/彈窗/選取/預覽/匯入/套用/還原/刪專案完整交互 | SCREEN-001～SCREEN-014 |
| 人工遊戲內 | 四類遊戲啟動並進入實際圖片場景，替換與還原後均確認 | FR-018, FR-019, FR-029 |
| 效能 | PoC記錄基準；V1依事先確認數據驗收 | FR-025, FR-026 |

單元測試不能代替實際檔案與遊戲驗證；E2E的假adapter不能作加解密通過證據。開發時選擇框架與腳本，本輪不預設命令已存在。

## 2. 測資與前置條件

每個遊戲使用可拋棄乾淨副本；保存引擎版本、部署方式、資產根、測試場景路徑/操作步驟、Windows版本、機器規格、檔案清單與hash。不得對日常使用的唯一遊戲副本注入故障。

每格至少三張可定位的圖片，包含透明PNG；另備不同資料夾同名、不同尺寸/比例/透明通道、非PNG、改名偽PNG、APNG、截斷/損毀PNG、不可讀檔。大尺寸樣本需記錄實際尺寸，不能無限消耗記憶體。加密樣本需有合法可用的標準配置；錯誤key/標頭用作負例，不將破解自訂加密列為需求。

| 矩陣ID | 引擎 | 遊戲圖片 | PoC必過內容 | 狀態 |
|---|---|---|---|---|
| MV-U | MV | 未加密靜態PNG | 完整循環＋遊戲確認＋還原位元組一致 | NOT RUN，樣本待備 |
| MV-E | MV | 標準內建加密圖片 | 解密預覽/PNG匯出/匯入/編碼套用/遊戲確認/原加密檔還原 | NOT RUN，樣本待備 |
| MZ-U | MZ | 未加密靜態PNG | 完整循環＋遊戲確認＋還原位元組一致 | NOT RUN，樣本待備 |
| MZ-E | MZ | 標準內建加密圖片 | 解密預覽/PNG匯出/匯入/編碼套用/遊戲確認/原加密檔還原 | NOT RUN，樣本待備 |

先未加密，再標準加密。差異PNG在PoC只要求明示/接受/拒絕的匯入行為；完整遊戲循環使用同規格替換。兩者不能混為「所有差異圖片遊戲顯示均正確」。

- 需求：FR-001；階段：MVP；模組：PROJECT。

## 7. 通過、失敗及報告

PoC通過：四格完整循環、PNG輸入限制、未套用不寫遊戲、操作前恢復、原始位元組還原、非目標不變、遊戲內確認全部具證據。任一資料完整性/恢復必要案例FAIL則不通過。缺樣本或環境為BLOCKED/NOT RUN，不可算通過。

MVP通過：完成所有FR對應案例及必要異常；無阻斷性資料遺失/誤寫/誤刪缺陷。V1的擴充測試不允許替代MVP已要求安全機制。大型效能未定門檻前只報量測，不報達標。

測試報告欄位：版本/commit、日期、執行者、Windows/引擎/樣本矩陣、案例ID、前置資料、實際步驟、預期/實際、PASS/FAIL/BLOCKED/NOT RUN、hash/日誌/截圖證據、缺陷與重測。證據不包含不必要的私有金鑰或不可分享遊戲素材。

文件交叉檢查與本計畫的應用測試不同；文件的PASS僅表示引用/一致性檢查通過。
