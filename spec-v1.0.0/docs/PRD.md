# RPG Maker 圖片替換工具 — PRD

版本：1.0.0｜日期：2026-10-22｜決策基準：R0.9（R0.8＋最後刪除決策1A/2B/3B）

狀態：正式規格初稿，待整體文件審核；產品決策已確認不等於已實作。此檔為產品行為唯一權威來源。

## 1. 定位、使用者與範圍

本機桌面工具，用於整理 RPG Maker 遊戲圖片、匯出供外部編輯、匯入靜態 PNG 替換、檢視歷史、安全套用與還原。主要使用者為需要處理本機遊戲圖片的使用者；玩家/Mod製作者/開發者的市場優先順位未另行定案，不影響本次操作規格。

不提供內建繪圖或AI生成，不透過改副檔名假裝格式轉換。原始資料夾分類與自訂群組並存；素材替換不修改遊戲事件、程式或外掛。

### 分期

| 階段 | 必要交付 | 排除/限制 |
|---|---|---|
| PoC | Windows；MV與MZ各自未加密/標準加密；選遊戲→掃描→預覽→匯出→匯入→檢查→安全套用→遊戲內確認→還原；至少三張部分失敗/重啟恢復 | 已知乾淨小型樣本；同規格靜態PNG完整循環，差異PNG僅要求接受/拒絕匯入驗證；不要求全部MVP畫面 |
| MVP | FR-001～FR-030的主要產品行為；MV/MZ與Windows；多專案/群組/歷史/批量/持久化/重新連結/刪除專案 | 僅可解碼靜態PNG；安全性不可延期到V1 |
| V1 | 大型素材效能、擴充邊界與異常覆蓋 | 數量、設備及時間門檻須先定，不能取代MVP基本安全驗收 |
| Future | macOS、Linux、其他RPG Maker版本、其他格式轉換、動畫替換與播放 | 僅保留方向，不承諾實作或相容；自訂加密/封裝尚無支援承諾 |

## 2. 核心語意與不變規則

- original：首次保存的原始檔案位元組與相對路徑，專案內唯一原圖基準，不被替換圖或遊戲更新覆寫。
- active：使用者目前選用的替換版本，可以為空。
- deployed：最後成功寫入並驗證的遊戲狀態，可為原圖或版本。外部衝突及中斷時另標示不可信/待恢復，不以舊標籤冒充現況。
- pending：有active且與deployed不同；active為空時不可自動還原遊戲。
- upload/import：保存專案版本；apply：寫入遊戲；restore：回到最初原圖；recovery：回到本次操作前狀態。
- 接受差異只接受可解碼靜態PNG的尺寸/比例/透明通道差異，不可解除格式、動畫或解碼阻擋。
- 正常操作只有明確套用、還原、恢復會寫遊戲。刪除專案只清工具資料，不修改遊戲。
- 專案存在期間禁止刪除原始基準；FR-030整個專案刪除是使用者明確批准的例外。
- 正常歷史刪除禁止刪active或deployed版本；整個專案刪除是例外，不得混用兩種警告。

## 3. 功能需求與驗收條件

各列驗收為必要條件，不表示已執行。PoC→MVP表示先驗證技術子集，再完成產品交互。

### FR-001 多專案管理

階段：MVP。

需求：專案的素材、群組、版本、進度互相隔離，可建立、開啟、切換。

驗收：建立兩個專案並修改其中一個；另一專案的資料及遊戲雜湊不變。

測試：[TC-001](TEST_PLAN.md#tc-001)；架構模組：PROJECT。

### FR-002 建立專案與素材讀取

階段：PoC→MVP。

需求：指定遊戲位置與名稱；首次建立固定原始基準。PoC 使用已知乾淨副本；MVP 要求使用者確認來源未修改，但不宣稱已驗證官方原版。

驗收：四類支援樣本可建立清單；不支援引擎、無法讀取位置有原因；掃描不改遊戲。

測試：[TC-002](TEST_PLAN.md#tc-002)；架構模組：PROJECT,ENGINE。

### FR-003 原始資料夾分類

階段：PoC→MVP。

需求：保留原始相對路徑，以原始資料夾分類，不搬動遊戲素材。

驗收：不同路徑同名素材保持獨立，分類與來源路徑一致。

測試：[TC-003](TEST_PLAN.md#tc-003)；架構模組：CATALOG。

### FR-004 多群組管理

階段：MVP。

需求：一圖可屬多群組；建立、加入、移除、刪除群組只改關聯，不刪素材、版本、歷史或遊戲檔案。

驗收：從群組A移除後群組B與版本仍存在；刪除群組不改遊戲。

測試：[TC-004](TEST_PLAN.md#tc-004)；架構模組：CATALOG。

### FR-005 多列對照工作臺

階段：MVP。

需求：每列為勾選、固定原圖、目前替換圖、詳細內容；沒有選用版本時顯示空狀態，已部署版本另顯示。

驗收：多筆配對正確；清空選用但仍有部署時不可標示遊戲已還原。

測試：[TC-005](TEST_PLAN.md#tc-005)；架構模組：UI。

### FR-006 素材詳細內容

階段：MVP。

需求：每列可進入正確詳細頁；刪除無功能的查看對照按鈕。返回保留工作臺上下文。

驗收：開啟正確素材、路徑、資訊與歷史；不存在無功能的查看對照入口。

測試：[TC-006](TEST_PLAN.md#tc-006)；架構模組：UI。

### FR-007 單張匯入與版本

階段：PoC→MVP。

需求：僅接受正常解碼的靜態PNG；保存來源；每張素材由V1單調遞增，刪除不重用號碼。成功匯入設為目前選用版本。

驗收：匯入增加一版；同一素材刪除V2後不重用V2；其他素材獨立編號；遊戲不變。

測試：[TC-007](TEST_PLAN.md#tc-007)；架構模組：IMPORT,VERSION。

### FR-008 圖片檢查

階段：PoC→MVP。

需求：檢查解碼、實際PNG格式、動畫標記、尺寸、比例、透明通道；PNG規格差異列出原值與新值，使用者接受才匯入。非PNG、APNG、損毀圖片阻擋，不可忽略。

驗收：假副檔名、GIF/WebP/JPG、APNG及損毀樣本均阻擋；差異未接受不可匯入，接受後可匯入。

測試：[TC-008](TEST_PLAN.md#tc-008)；架構模組：IMAGE。

### FR-009 版本歷史與刪除保護

階段：MVP。

需求：歷史可查看、選用、刪除；目前選用或目前已部署版本禁止刪除。選用歷史需確認，不直接寫遊戲。

驗收：已選用與已部署版本均不可刪除；其他版本可刪除；切換選用只更新待套用狀態。

測試：[TC-009](TEST_PLAN.md#tc-009)；架構模組：VERSION。

### FR-010 歷史大圖預覽

階段：MVP。

需求：大尺寸彈窗，初始適合畫面、完整圖片可見；支援加減、100%、適合畫面、滾輪、拖曳、右上角×與Esc。

驗收：預覽及關閉不改選用版本；縮放後可查看局部，關閉返回原上下文。數值上限待實測。

測試：[TC-010](TEST_PLAN.md#tc-010)；架構模組：UI,IMAGE。

### FR-011 取消目前替換

階段：MVP。

需求：確認後清空目前選用，保留全部歷史與已部署遊戲狀態。

驗收：active清空、歷史不減、遊戲雜湊不變；不把取消替換當還原。

測試：[TC-011](TEST_PLAN.md#tc-011)；架構模組：VERSION。

### FR-012 搜尋篩選

階段：MVP。

需求：檔名搜尋；資料夾/群組範圍；全部、待套用、有注意事項、尚未替換、已套用篩選。篩選條件改變清空選取。

驗收：結果符合條件；空結果提示；全選限目前列表；篩選改變後不存在隱藏選取。

測試：[TC-012](TEST_PLAN.md#tc-012)；架構模組：CATALOG,UI。

### FR-013 批量匯入配對

階段：MVP。

需求：畫面配對表，不含CSV/JSON清單匯入。按相對路徑唯一配對，否則人工指定或略過；重複目標阻擋。已確認批次執行失敗整批撤回。

驗收：不同路徑同名不猜配；無效圖及未接受差異不可提交；中途失敗不留下部分可見版本或選用變更。

測試：[TC-013](TEST_PLAN.md#tc-013)；架構模組：IMPORT。

### FR-014 單張及批量匯出

階段：PoC→MVP。

需求：詳細頁匯出單張；批量可選選取項目、目前範圍、整個專案。先檢查目的地同名衝突，供覆蓋、略過或取消。

驗收：輸出數量與範圍符合選擇；取消不寫入；略過不改舊檔；失敗列出實際完成與未完成項目，不假稱全部成功。

測試：[TC-014](TEST_PLAN.md#tc-014)；架構模組：EXPORT。

### FR-015 匯出版本與路徑

階段：PoC→MVP。

需求：可選原圖或目前選用版本；無選用時回退原圖並標明來源。保留原始檔名主體及相對路徑，加密素材匯出可編輯PNG。

驗收：原圖來自固定基準；同名不同路徑無碰撞；目前版本不誤用已部署版本。

測試：[TC-015](TEST_PLAN.md#tc-015)；架構模組：EXPORT,ENGINE。

### FR-016 預覽背景

階段：MVP。

需求：棋盤格、白、黑、自訂背景，不改圖片本身。

驗收：切換背景後圖片內容、版本、遊戲雜湊皆不變。

測試：[TC-016](TEST_PLAN.md#tc-016)；架構模組：UI。

### FR-017 自動儲存與續作

階段：PoC必要紀錄→MVP。

需求：成功修改後持久化；重啟恢復已成功保存的專案、群組、版本與選用。PoC至少持久化基準、操作與恢復必要狀態。

驗收：重啟資料一致；未落盤不得顯示已儲存；自動儲存不修改遊戲。

測試：[TC-017](TEST_PLAN.md#tc-017)；架構模組：STORE。

### FR-018 套用全部待套用項目

階段：PoC→MVP。

需求：獨立確認頁顯示目標與全部待套用清單；明確確認後才寫遊戲。寫入前可取消，開始寫入後暫停取消與正常關閉直到完成/恢復。

驗收：只改清單目標；遊戲實際顯示替換；無待套用項目不能執行；寫入中不允許其他衝突修改。

測試：[TC-018](TEST_PLAN.md#tc-018)；架構模組：OPERATION。

### FR-019 備份與原圖還原

階段：PoC→MVP。

需求：保存原始位元組；可勾選部分或全選已部署素材還原至固定原圖，保留替換與歷史。還原也需外部衝突檢查及安全恢復。

驗收：還原後與原始檔案位元組相同；遊戲內確認正常；其他素材不變；備份缺失或不可信不得寫入。

測試：[TC-019](TEST_PLAN.md#tc-019)；架構模組：OPERATION,STORE。

### FR-020 原圖/選用/部署分離

階段：PoC→MVP。

需求：原始基準固定，選用版本與部署狀態獨立。待套用為有選用且不同於已部署；無選用不表示遊戲為原圖。

驗收：匯入不更新部署；成功套用後才更新部署；還原後選用仍保留並可再套用；預覽不更改任一狀態。

測試：[TC-020](TEST_PLAN.md#tc-020)；架構模組：VERSION,STORE。

### FR-021 外部變更阻擋

階段：PoC→MVP。

需求：套用及還原前，比對遊戲目前檔案與最後可信狀態；不同/缺失則阻擋並說明，不允許勾選強制覆蓋。

驗收：外部修改、刪除目標均被識別；衝突批次未開始寫入；原始基準不被外部檔案覆寫。

測試：[TC-021](TEST_PLAN.md#tc-021)；架構模組：ENGINE,OPERATION。

### FR-022 失敗與中斷恢復

階段：PoC→MVP。

需求：失敗回到本次操作前狀態，不一定為最初原圖。重啟提示，使用者啟動恢復；受影響專案鎖定修改。恢復失敗保留資料，允許檢視/重試/關閉，另有FR-030明確放棄例外。

驗收：至少三張圖片部分寫入失敗與程序中斷可識別；可用儲存環境下恢復雜湊一致；失敗不宣稱成功。

測試：[TC-022](TEST_PLAN.md#tc-022)；架構模組：OPERATION。

### FR-023 位置重新連結與唯一性

階段：MVP。

需求：一個遊戲位置一個專案；重新連結檢查引擎、素材路徑與紀錄一致性，不符阻擋。遊戲更新不重設原基準；另準備乾淨位置建新專案。

驗收：搬移相同遊戲可保留資料；錯誤遊戲/重複位置被阻擋；不偷偷更新基準。

測試：[TC-023](TEST_PLAN.md#tc-023)；架構模組：PROJECT,ENGINE。

### FR-024 儲存失敗管理

階段：PoC必要保護→MVP。

需求：失敗允許檢視與重試；停止新增修改及套用/還原。關閉彈窗：重試、取消、放棄未儲存變更並關閉。放棄不代表解除未完成遊戲寫入紀錄。

驗收：錯誤狀態不顯示已儲存；寫入被阻擋；重試成功恢復；放棄後重啟為最後可信狀態或進入恢復。

測試：[TC-024](TEST_PLAN.md#tc-024)；架構模組：STORE,UI。

### FR-025 大量素材效能

階段：MVP基本→V1量化。

需求：列表與縮圖避免全量原圖常駐；PoC小型有紀錄樣本；V1再定大型素材與效能門檻。虛擬列表是技術建議。

驗收：PoC記錄樣本量、耗時及峰值記憶體；未有大型測試不可宣稱大型支援已驗證。

測試：[TC-025](TEST_PLAN.md#tc-025)；架構模組：IMAGE,CATALOG,UI。

### FR-026 掃描取消與逐檔錯誤

階段：MVP。

需求：掃描可取消；單檔讀取/解碼失敗列出原因，其他可讀素材可繼續；未完成基準的素材不可套用。

驗收：取消停止新增工作並回報已完成數；壞檔可定位；不可將半份備份標為可還原。

測試：[TC-026](TEST_PLAN.md#tc-026)；架構模組：ENGINE,CATALOG。

### FR-027 彈窗與獨立頁面

階段：MVP。

需求：一般確認、群組增刪等使用彈窗；套用/還原採應用內獨立頁面，不開OS視窗。返回保留群組、篩選及捲動位置。

驗收：一般確認不跳主頁；套用還原返回上下文正確；取消不產生操作副作用。

測試：[TC-027](TEST_PLAN.md#tc-027)；架構模組：UI。

### FR-028 置頂工具列

階段：MVP。

需求：依 Mockup 排列並參考 W6：搜尋→篩選→背景→批量匯入→匯出；選取列下方為捲動素材清單；群組刪除在群組選單。

驗收：長列表仍可操作匯入/匯出；不沿用W5底部批量匯入。

測試：[TC-028](TEST_PLAN.md#tc-028)；架構模組：UI。

### FR-029 MV/MZ相容性與平台

階段：PoC→MVP。

需求：Windows支援MV/MZ標準靜態PNG及內建加密素材；四格矩陣都驗證。其他引擎/平台/自訂加密封裝不屬本版。

驗收：四格均完成預覽、匯出、匯入、套用、遊戲內確認及位元組還原；非支援格式明確回報。

測試：[TC-029](TEST_PLAN.md#tc-029)；架構模組：ENGINE。

### FR-030 刪除專案與資料清理

階段：MVP。

需求：警告並確認後刪專案DB與專屬備份、上傳圖、版本、縮圖、操作紀錄；不刪遊戲、外部來源、匯出檔或其他專案。可保留部署結果刪除，亦可明確放棄未完成恢復後強制刪除。

驗收：二次風險確認揭露永久失去還原/恢復能力與可能部分修改；取消不刪；清理不寫遊戲；失敗不假稱全部清除。

測試：[TC-030](TEST_PLAN.md#tc-030)；架構模組：DELETE,PROJECT,STORE。

## 4. 操作流程

1. 首頁建立專案→使用者確認未修改來源→選遊戲位置→識別引擎→掃描並保存原始基準→進工作臺。失敗檔案列出，不視為可安全替換。
2. 工作臺選資料夾或群組→搜尋/篩選→選素材→單張或批量匯出→外部工具編輯PNG。
3. 單張詳細頁上傳→格式/差異檢查→接受必要差異→保存版本與active。批量則先配對、略過不處理項、解決重複目標，再整批提交。
4. 歷史預覽只開大圖；選用版本需確認；取消目前替換清active但保留deployed。
5. 套用頁列全部pending與目標位置→檢查原始備份、外部變更、儲存狀態→確認→寫入與驗證→成功後更新deployed。中途失敗走recovery。
6. 還原頁選部分/全部→檢查外部變更與基準→確認→寫入原始位元組→驗證；active/歷史保留。
7. 重啟發現未完成操作→鎖受影響專案修改→提示使用者開始恢復→恢復操作前位元組→驗證。失敗可檢視、重試、關閉，或走明確放棄與刪除例外。
8. 刪除專案→展示清理範圍及不可逆結果→若仍有部署或未恢復，另確認保留遊戲現況/放棄恢復→刪除專屬資料。不能默默還原遊戲或刪外部資料。

### 工作臺與視覺

頂部：專案首頁/專案切換、儲存狀態、設定、還原、套用。左欄：原始資料夾與自訂群組。群組標題提供新增素材及群組選單，刪群組置於選單。固定工具列順序：搜尋、狀態篩選、背景、批量匯入、匯出；選取列含全選/數量/群組操作；素材列表獨立捲動。

視覺採既有深色專業素材管理方向：石墨背景、密集但可讀資訊、圖片優先、低彩度薄荷色主要操作、琥珀色注意。色碼/尺寸以既有Mockup作參考，不把生成圖片中的錯字當規格。W6的明暗CSS不是取代已選深色視覺的決策。

## 6. 狀態與錯誤行為

| 情境 | 可做 | 不可做/結果 |
|---|---|---|
| 無替換圖 | 上傳、原圖匯出、查看歷史 | 不自動還原已部署版本 |
| 規格差異 | 顯示原/新值，接受或取消 | 未接受不可匯入 |
| 非PNG/APNG/損毀 | 說明並重新選檔 | 不允許忽略繼續 |
| 自動儲存失敗 | 檢視、重試、關閉確認 | 禁止新增修改及遊戲寫入 |
| 外部變更 | 顯示檔案與衝突原因 | 套用/還原均阻擋，不提供強制覆蓋 |
| 寫入中 | 查看進度 | 暫停取消、正常關閉、並行衝突操作 |
| 重啟待恢復 | 檢視、開始恢復、關閉；或FR-030例外 | 一般修改與新套用阻擋 |
| 恢復失敗 | 檢視、重試、關閉、明確放棄並刪專案 | 不宣稱成功，不自動清備份 |
| 匯出部分失敗 | 報告實際完成/略過/失敗 | 不假稱整批成功；是否提供失敗重試UI待細化 |
| 專案刪除部分失敗 | 清楚標記未清完、保留足以重試的清理狀態 | 不顯示全部清除、不掃除不屬該專案的檔案 |

刪除警告必須列出專案名稱與清理類型，明示「工作紀錄、已儲存圖片與備份將刪除，無法透過此專案還原」。若有部署，追加「遊戲維持目前替換結果」；若未恢復，追加「遊戲可能僅部分修改；繼續將放棄恢復」。需明確二次確認，不默認勾選。實際寫入仍執行時不可同時清理其檔案；應先安全停止活動工作後才執行已授權的放棄刪除，此為競態防護而非要求先恢復。
